# Helios — project notes

M&A deal-sourcing assistant ("Helios", for Helbling). Real login, corpus, longlists, agent chat and spreadsheet imports against `../helios-gateway` (FastAPI), the one backend. Don't add other APIs or databases unless asked.

## Stack

- Next.js 16 (App Router, Cache Components on), React 19, Tailwind CSS v4 (CSS-first `@theme` in `src/app/globals.css`, no tailwind config file).
- Icons: **Feather only**, copied into `src/components/icons.tsx` (no `react-feather` dependency; same 24px grid and defaults, `size` prop). To add one, copy its SVG from feathericons.com there. If Feather lacks an icon, pick the closest Feather one and say so; don't add another icon set. One exception on request: the pushpin (`PinIcon` in `src/components/PinIcon.tsx`, from the dev branch), drawn in Feather's style; it marks pinned chats and prioritized values.
- Animation: `motion` (`motion/react`).
- Fonts (Google, via `next/font`): **Lora** (serif) for headings, the wordmark and the chat title, **DM Sans** for everything else, **DM Mono** for code-like bits (e.g. the exact web-search query on the approval card).

## Architecture

- **Auth:** `src/app/login/page.tsx` signs in with email and password against helios-gateway. `src/app/api/auth/login` and `/logout` keep the gateway's session token in an httpOnly cookie (`helios_session`, 30 days), and the gateway proxy turns it into `Authorization: Bearer`; page scripts never see the token, and the generic proxy refuses `/auth/*`. `src/lib/auth.ts` holds the signed-in user (`useUser()`: undefined while loading, null when signed out) and syncs its language into i18n. `AppShell` sends signed-out users to `/login`. Accounts come from the gateway's seed script or an admin on Settings → Members; there is no self sign-up ("Request access" stays inert).
- `src/app/(app)/layout.tsx` (server) wraps `AppShell` (`src/components/AppShell.tsx`, client: auth check, `<Sidebar>` and `<Workspace>`) in `<Suspense>`. The shell reads the URL and localStorage, so it renders only in the browser; without the Suspense the production build fails to prerender `/c/[id]`. The route pages under `(app)` (`/` and `/c/[id]`) render `null` and set `export const instant = false`. Keep it this way: the layout staying mounted is what lets the sidebar avoid remounting and the composer animate from home to chat.
- `src/components/Workspace.tsx`: home and chat in one tree. The mode comes from the URL plus an optimistic `pending` id, so the switch is instant on submit. Research mode opens when the session has `list_ids` (`SessionListPanel` embeds `LonglistDetail`).
- `src/lib/chat.tsx` + `src/lib/sessions.ts`: real gateway sessions (Recents). Home composer `POST /sessions`; `/c/[id]` loads the chat fresh (reload works). Only the chat on screen is streamed (SSE `/sessions/{id}/stream?after=` through the gateway proxy); going home closes it. If the stream drops, it catches up with `/events?after=<last seq>`, clears half-streamed text and reopens, backing off up to 10s. Busy chats elsewhere refresh the sidebar from `GET /sessions` every 4s (titles and status only). Stop → interrupt; question card ← `ask_user` / `request_web_research` via `pending_ask` (titles truncated to 120 chars; web approvals may show the exact query as detail); typed text on a web-approval card is an answer, not consent. Dismissing a card only hides it until reload. Pin/rename/delete hit the API.
- The sidebar reads `useChatList()` (titles only), never `useChat()`, so it doesn't re-render on every streamed token. Sample/fake recents are gone.
- `src/lib/useDismiss.ts`: shared outside-click/Escape handling for popovers.
- **Form controls:** `Select.tsx` (custom dropdown in the popover style: 36px rows, check on the right, an optional faint `hint` per option, `divider` lines and `group` headings; `searchable` adds a filter field at the top (accent-insensitive; letters type into it); keyboard arrows, Home/End, Enter/Space, a letter jumps; the list is a portal with fixed position, below or above the trigger, so a scrolling modal can't clip it) and `DateField.tsx` (a date you type, days first in both languages: 24.11.2026, also 24/11/26 or 2026-11-24; an impossible date, or one outside 1900 to today, isn't saved and gets the sky attention ring (a stored out-of-range date is flagged too, and the calendar then opens on today); days after today are disabled in the calendar; the calendar button opens a month (weeks start Monday), its title a twelve-year grid, plus "Today"). While either is open it handles keys on the window in the capture phase, so Escape closes the popover and never the modal around it (closing an import's modal cancels the import). Used everywhere in the import modal: the settings card ("Where is this data from?", "Also add to a longlist", "Data as of"), each mapping row's target (searchable, grouped like the catalogue: "This list", then the data points by entity) and each review row's decision.
- Settings (`/settings/profile`, `/settings/members`, `/settings` = profile): the route pages render `null` like the others; the `(app)` layout shows `SettingsPanel` (`src/components/Settings.tsx`) instead of `Workspace` on `/settings*`.

- **Dev-only admin area** (list imports by anyone also appear there, labelled "list import") (`/admin/imports`, `/admin/imports/[id]`, `/admin/master`; `src/components/admin/`, shown by `AppShell`): upload spreadsheets ("Into: Corpus / New longlist / Longlist: …"; every upload opens the `ImportModal`, corpus ones too), the imports list (Source shows an Other source's note, e.g. "other: Grasp"), revert versions, and browse master data with every value's sources. `/admin/imports/[id]` is a read-only history view for both targets (status, Into, By, Source with an Other source's note, as-of, catalogue, version, the report's numbers, the original file); while an import waits for review it has "Cancel import" and "Open review" (the modal, without cancel-on-close). It talks to helios-gateway through `src/app/api/gateway/[...path]/route.ts` (server-side proxy: `GATEWAY_URL`, default `http://localhost:8010`; adds `GATEWAY_SECRET` if set) via `src/lib/gateway.ts`. Who's a dev: the user's role from the gateway (member < admin < dev; a dev holds admin rights too, `is_admin`/`is_dev` on the user); others don't see the "Imports" sidebar item, are sent home from `/admin`, and get 403 from corpus imports and the imports list (list imports are open to everyone, through the import modal). The admin area is English-only (internal tool), except its sidebar label.

## Design rules (from the owner's feedback)

- **Palette:** greys, white, black and light blue only. Tokens live in `globals.css`: `ink`, `canvas`, `line`, `subtle`, `muted`, `faint`, `sky` (#dbe9fb: stripe, avatar, focus ring), `brand` (#c4d9f6: logo and loader only), `sky-ink`, `hairline` (#f3f4f6: the table's row separators, lighter than `line`), `sky-wash` (#f6faff: fill of the column the latest agent pass added), `sheet` (#00a552: green, for spreadsheets: the active table-tab icon (Feather `Table`), the drop overlay icon and spreadsheet file cards). `good` (#667537 olive green), `warn` (#e6ac22 yellow) and `bad` (#cc2237 red) are only for data-quality dots and status, taken from the owner's reference palette (earlier tries: pastels #c4f5d7/#f5e5c4/#f5c4c4 were too faint; #73e7a0/#eac885/#e15151 worked). Good data never gets a colour.
- **Favicon:** `src/app/icon.svg`, the same blue square as the logo.
- **Logo:** a plain square in `brand` blue with **sharp corners**, the `Logo` component. Never an image or a "G" mark. It appears in the sidebar and on login, not in the chat input.
- **Text size:** UI text is 13–15px. Reference screenshots may be retina/zoomed (the login reference was about 1.4×), so derive sizes from the actual viewport and don't copy pixel values blindly.
- **Precise alignment matters.** The owner notices 1–5px misalignments. Examples:
  - Optically centre icons against text cap height, not the line box (see the `-top-[3.5px]` on the login logo).
  - The copy button's hover background is flush with the message text (no negative margin).
- **Buttons are fully rounded** (`rounded-full`) across the app: toolbar buttons, Export, dialog and selection-bar buttons, Invite, login Continue, the question card's Dismiss and all admin buttons. Inputs, dropdown fields and menu rows keep `rounded-lg`.
- **No shadows** on the chat input. Popovers get a soft shadow, `border-line`, `rounded-xl` and `p-1`, with 36px rows.
- **Tooltips:** black background (`bg-ink`), white 12px text.
- **Feature labels** on login: the title and the subtext are one line each (`whitespace-nowrap`).
- **Login hero photo** (`public/login-background.png`) always fills the full panel height and crops the sides; keep a dark overlay so the white copy stays readable.

## Behaviour rules

- Composer: one boxed layout everywhere (home, chat, research): `rounded-2xl`, text on top, + bottom-left (grey circle only on hover) and send bottom-right. The pill layout was removed on request. Home keeps its typed-out example prompts; the + menu opens downward there and upward elsewhere.
- The textarea grows with its text, smoothly (150ms height transition, measured at height 0 since `auto` can't animate), up to 40% of the window, then scrolls. Don't give it `flex-1`: in the boxed (column) layout that pins it at its 44px minimum.
- Chat input is a multiline textarea: **Enter sends, Shift+Enter inserts a newline.** With nothing to send, Enter passes through to an open question card (which picks its highlighted answer). Hovering send shows a tooltip "Send" with a ↵ key icon.
- Home greeting is randomised per visit: "Good morning/afternoon/evening, Vanya" or a tagline ("What's your next move?", "Happy to Helbling", "Need a Helbling hand?", "An Excel-lent day!"; "Better than CoPilot" was removed as too demeaning). The name is the signed-in user's first name.
- User messages: light grey bubble. AI messages: plain text with no bubble, and a copy button underneath (tooltip "Copy"; on click the icon pops into a check and the tooltip hides).
- The chat title (from the first message) shows in serif (Lora) in the main header (there is no search bar), with the web search status at its right (`WebStatus`; in research mode at the right of the chat column's title row): a `sky-ink` globe while web search is allowed (for the chat, this run or one search, replayed from the card answers in the log, since run and one-search grants end with the run), a `faint` globe otherwise (Feather has no globe-x; only the colour changes). It's a round button: a click turns web search on or off for the whole chat (`setWebSearch` → `POST /sessions/{id}/web_access`, a `user.web_access` event), and its black tooltip says what a click does ("Turn web search on" / "Turn web search off"), opening to the left because the header clips below, with a gradient fade under the header. The thread has the mirrored fade at the bottom, so messages fade out as they scroll under the composer.
- **Citations** (`src/components/Citation.tsx`): `[[source | url | evidence]]` in agent text (chat messages via `Markdown`, streaming text and list cells via `CitedText`) renders as a small grey numbered chip; hover/focus/click opens a dark portal popover (header: Feather `Globe` + "Web research" + the site's host, linking to the page, or `Database` + the person/provider for internal data; body: the evidence). Numbered per text; a marker that doesn't parse stays as text; copying a message strips markers. Editing a cell shows the raw markers.
- The step list behind "Working… / Worked for Ns" (research and intake) sits in one box: `border-line`, `rounded-xl`, `px-3 py-2.5`. A run the user stopped reads "Stopped after Ns"; one that ended in an error (e.g. the model's rate limit) reads "Failed after Ns", followed by the gateway's plain-English error.
- Thinking loader: the logo square split 3×3; corners, edges and centre fade as groups (hollow → corners → X → dot → plus → full), about 0.62s per cycle in ~59ms steps: corners, X, dot and plus hold one step each, the hollow square holds half a step, the full square only passes through, and each of the six fades takes one step.
- Recents: the "Recents" label is a toggle with a small chevron after it (pointing right while collapsed); the list fades in and out. Titles are grey (`muted`) and turn ink on hover; the open chat is ink on its grey pill; rows are 1px apart so hover backgrounds don't touch. The research column's title has no "…" menu.
- Recents rows (`RecentRow` in `Sidebar.tsx`): hovering shows a ⋮ button opening Pin/Unpin, Rename and Delete (persisted on the gateway). Pinned chats move to the top. A pulsing `brand` dot while the chat is running. `useChatActions` / `useChatList` (`pinned`, `busy`, `hasList`).
- Sidebar width: 272px, narrowing to 208px while the open chat shows its buyer table; the user menu has extra top padding and a `canvas` gradient above it, so recents fade out behind it (no rule).
- The sidebar collapses to a 52px rail. When collapsed, hovering the logo morphs it into the sidebar icon, and clicking it expands the sidebar again.
- Conversation flow (real agent):
  - Titles come from the gateway (first message; "Name: …" → "<Name> Buyer Longlist").

- Settings: the user menu's "Settings" opens `/settings/profile`. - **Employee ranges (display):** Employees is a `{low, high}` object (`formatValue` → `formatRange` in `src/lib/corpus.ts`): `37` for an exact figure, `11–50` (en dash), `10,001+` for no upper bound and `up to 9` (i18n string) for no lower bound, numbers through the locale formatter (Swiss `10'001+`). Closing before rating dismisses the ask for that chat for good (saved on the gateway, not localStorage). `useChat().feedbackFor(id)` holds what the gateway said (`feedback` on `GET /sessions/{id}`: null = not asked yet). Devs read it in `helios-evals`.

- **Languages (i18n):** `src/lib/i18n.ts` holds every interface string; keys are the English text with `{name}` placeholders, and the `DE` map must translate each (the type enforces it). Use `const { t, formatNumber, formatDate } = useI18n()`; type label fields as `MessageKey`. The choice (Settings → Profile → Language: English/Deutsch) is stored in localStorage and shared through an external store, so there's no provider; `<html lang>` follows it. German uses Swiss spelling (ss, no ß), the formal "Sie", and Swiss numbers (1'662). **Agent output stays as written** in both languages: messages, question-card copy, chat titles, table data and version commit messages. Only the dates in data are localised (month names).

Types and helpers in `src/lib/longlists.ts`. Lists come from imports for now (the mapping review's "Longlist" setting: None / New list… with a name / an existing list).

The table reuses the research table's look (grouped sticky headers, sticky checkbox and name column, truncation hover box, dot geometry, header ⋮ menu with filter/sort/Remove column, drag to reorder, selection bar). ## Working conventions

- Verify UI changes visually, not just with `tsc`/lint. A quick way: a throwaway Playwright script (`playwright-core` with the system Chrome at `/Applications/Google Chrome.app`) that logs in, then screenshots at 1440×900, DPR 2. Keep such tooling out of the project's dependencies.
- **Tailwind v4 pitfall:** don't put a `/* comment */` on the same line as a `--color-*` token inside `@theme`; Tailwind silently drops the token. Put comments on their own line.
- If styles look stale after editing `globals.css`, restart `next dev`.
- `LayoutProps`/`PageProps` are generated types. If `tsc` can't find them, run `next build` or `next dev` once.
- When an instruction is ambiguous (e.g. which element "the rectangle" is, or the direction of an "inset"), take the most conventional reading and say what you assumed in one line, so it's quick to correct.
